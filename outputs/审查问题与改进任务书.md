## 一、🔴 Q1：问题三收敛曲线与结论矛盾

### 1.1 问题描述

**数据矛盾**：

```
problem3_convergence.csv:
  Gen 0:  best_fitness = -0.000560  →  P/A = 560 W/m²
  Gen 14: best_fitness = -0.000590  →  P/A = 590 W/m²
  （仍在下降，未收敛）

problem3_result.json:
  结论 = "Uniform configuration is optimal"
  实际 P/A = 525.85 W/m²
```

DE 找到的异构解 P/A = 560~590 W/m² **全部高于**均一解的 525.85 W/m²，但最终结论却说"均一最优"。且只跑了 15 代，Gen 14 仍在下降，未收敛。

### 1.2 根因分析

最可能的原因：**DE 找到的高 P/A 异构解不满足 P̄ ≥ 60 MW 约束**（镜更小/更少 → 单位面积效率高但总功率不足）。但这些解在收敛曲线中被记录为"best_fitness"，说明目标函数可能没正确加入功率约束的罚项。

### 1.3 性能问题与方案选择

> **⚠️ 重要**：原方案的"DE 50 代 + popsize=15 + 完整 60 采样"会导致性能瓶颈。
> 完整 60 采样的单次仿真约 53s，50 代 × popsize 15 = 750 次调用，总耗时约 **11 小时**，不可接受。

**采用折中方案**：校准 + 两阶段 DE
- **阶段 1**（noon-only 快搜）：用 12 正午采样 + 校准约束，快速搜索 40 代
- **阶段 2**（full-60 精修）：用完整 60 采样，以阶段 1 结果 warm-start，精修 10 代
- **总耗时约 3.5 小时**，比原方案快 3 倍，且约束判断准确

### 1.4 实施步骤

#### 步骤 1：校准 noon-only 与 full-60 的功率关系

已有数据证明 noon-only 普遍比 full-60 高约 7%：

```
baseline (W=6, h=3, n=25):
  noon-only P = 65.19 MW  (虚高)
  full-60  P = 60.58 MW  (实际)
  比值 k = 60.58 / 65.19 = 0.9293
```

在 n_rings=25 附近取 3-5 个采样点，同时算两种模式，拟合校准系数：

```python
# 校准：在问题二最优解附近取多个点，确定 noon→full 的转换系数
calibration_points = []
for n_rings in [23, 25, 27]:
    params = {'x_t': 0, 'y_t': 0, 'W': 6.0, 'h_inst': 3.0, 'n_rings': n_rings}
    P_noon = annual_simulation(params, sampling='noon_12').P_avg_MW
    P_full = annual_simulation(params, sampling='full_60').P_avg_MW
    calibration_points.append((P_noon, P_full))
    print(f"n_rings={n_rings}: noon={P_noon:.2f}, full={P_full:.2f}, ratio={P_full/P_noon:.4f}")

# 拟合线性关系: P_full ≈ k * P_noon
CALIBRATION_RATIO = np.mean([f/n for n, f in calibration_points])
# 预期 k ≈ 0.92-0.93
print(f"校准系数 CALIBRATION_RATIO = {CALIBRATION_RATIO:.4f}")
```

**关键**：校准后，约束阈值从 `P_noon >= 60` 改为 `P_noon * k >= 60`，即 `P_noon >= 60/k ≈ 64.5`。

#### 步骤 2：修改 fitness 使用校准后阈值（noon-only 模式）

```python
CALIBRATION_RATIO = 0.93  # 用步骤1的实际结果替换

def fitness_heterogeneous_noon_calibrated(params):
    """阶段1用：noon-only 快速评估 + 校准约束"""
    P_noon, P_per_area_noon = simulate(params, sampling='noon_12')
    P_full_estimated = P_noon * CALIBRATION_RATIO  # 估算实际功率

    penalty = 0
    if P_full_estimated < 60.0:
        penalty = (60.0 - P_full_estimated) * 1e4  # 大数罚项

    return -(P_per_area_noon - penalty)

def fitness_heterogeneous_full(params):
    """阶段2用：full-60 精确评估 + 真实约束"""
    P_full, P_per_area_full = simulate(params, sampling='full_60')

    penalty = 0
    if P_full < 60.0:
        penalty = (60.0 - P_full) * 1e4

    return -(P_per_area_full - penalty)
```

**验收**：
- fitness 函数包含功率约束罚项（罚系数 1e4）
- 阶段 1 的约束阈值经过校准（`P_noon * k >= 60`）

#### 步骤 3：两阶段 DE 运行

```python
# ===== 阶段 1：noon-only 快搜（40 代）=====
result_phase1 = differential_evolution(

    polish=True,                      # 最后用 L-BFGS-B 精修

final_result = result_phase2
```

#### 步骤 4：callback 记录完整信息（含双模式验证）

```python
def convergence_callback_phase1(intermediate_result):
    """阶段1回调：每代记录 noon-only，每5代补 full-60 验证"""
    gen = intermediate_result.generation
    best_x = intermediate_result.x

    P_noon, PA_noon = simulate(best_x, sampling='noon_12')

    # 每5代才跑 full-60（省时间），其余用校准估算
    if gen % 5 == 0 or gen == 39:
        P_full, PA_full = simulate(best_x, sampling='full_60')
        constraint_real = P_full >= 60.0
    else:
        P_full = None
        PA_full = None
        constraint_real = None  # 未验证

    P_full_est = P_noon * CALIBRATION_RATIO
    log = {
        'generation': gen,
        'phase': 1,
        'best_fitness': intermediate_result.fun,
        'P_noon_MW': P_noon,
        'P_per_area_noon': PA_noon,
        'P_full_estimated_MW': P_full_est,
        'P_full_actual_MW': P_full,        # 每5代有值，其余 None
        'P_per_area_full': PA_full,
        'constraint_estimated': P_full_est >= 60.0,
        'constraint_actual': constraint_real,
    }
    history.append(log)

def convergence_callback_phase2(intermediate_result):
    """阶段2回调：每代都记录 full-60（精修阶段代数少）"""
    gen = intermediate_result.generation
    best_x = intermediate_result.x

    P_full, PA_full = simulate(best_x, sampling='full_60')

    log = {
        'generation': gen + 40,  # 接着阶段1编号
        'phase': 2,
        'best_fitness': intermediate_result.fun,
        'P_noon_MW': None,
        'P_per_area_noon': None,
        'P_full_estimated_MW': None,
        'P_full_actual_MW': P_full,
        'P_per_area_full': PA_full,
        'constraint_estimated': None,
        'constraint_actual': P_full >= 60.0,
    }
    history.append(log)
```

## 四、🟡 Q4：效率乘积校验偏差

### 4.1 问题描述

```
eta_total     = 0.5256  (直接对总效率求平均)
product_check = 0.5213  (五项分别平均后相乘)
差距：0.0043 (0.82%)
```

### 4.2 实施步骤

这是 Jensen 不等式效应，**非计算错误**，只需在报告中加脚注。

**操作**：在 `outputs/` 下创建 `efficiency_note.md`：

```markdown
## 效率乘积偏差说明

| 指标 | 值 |
|------|-----|
| eta_total (总效率直接平均) | 0.5256 |
| product_check (分量平均后相乘) | 0.5213 |
| 偏差 | 0.82% |

### 原因

由于各效率分量（η_cos, η_sb, η_trunc, η_at）在时间上非独立
——它们都在正午最高、早晚最低——因此：

  E[η_cos · η_sb · η_trunc · η_at] ≠ E[η_cos] · E[η_sb] · E[η_trunc] · E[η_at]

这是 Jensen 不等式的体现。总效率直接平均（0.5256）是正确值，
分量乘积（0.5213）仅供分解贡献参考。

### 引用建议

报告正文用 η̄ = 0.5256。
脚注："分量均值之积（0.521）与总效率均值（0.526）存在约 0.8% 偏差，
系各效率时间相关性导致的 Jensen 不等式效应，非计算误差。"
```
